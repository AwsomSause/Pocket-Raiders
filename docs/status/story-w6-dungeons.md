# W6: Expeditions and dungeons

- `src/data/dungeons.json`: **8 basic** (3 to 5 rooms) and **8 themed** (6 to 9 rooms, boss at the end) dungeons from design 14.16, as authored node graphs with branches. Node kinds: wild, trainer, cache, rest, mystery, puzzle, trap, den, rare, hidden, boss, exit.
- `core/dungeon/schema.ts` validates each one at load (a bad file stops the build): size by kind, exactly one exit, 3+ node kinds, every room reachable and every branch reaches the exit, no loops, no 3 wild rooms in a row, a hidden room is always a side branch, themed needs a boss.
- `core/dungeon/compile.ts` turns each room into a room event (`stop: dungeon`, `room: true`) run by the normal event engine and UI. A room's choices are its exits; taking one pays the room (wild/den/rare/trainer/boss battle, loot, heal, Intelligence check for puzzle and trap) and opens the next room with `addEvent`. Hidden rooms need a Key Charm. A trap can be skipped with an Escape Rope. Rewards: tier potion class, the dungeon's supply item, boss reward. A dungeon is not a stage: no stage index, no badge, no level cap.
- Gates: W5 events **Abandoned Expedition** (opens a random basic dungeon) and **Hidden Dungeon** (secret, needs a Key Charm, opens a random themed one) are now enabled.
- Limits: dungeons run through the event engine, not the Mega-Expedition screen (`run.expedition` is untouched, so no extraction/loot-on-failure rule; leaving a dungeon midway just means not taking the next exit). The design's new items (`torch`, `dungeon_key`, `supply_pack`) are not added: the Key Charm is the key and Escape Rope/Repel are the supplies; dark rooms are not modelled. A gate may open the same dungeon twice in a run (`addEventFrom` is random). Tiers 1 to 4 set the level bonus (+0/+2/+4/+6); rarity bias and relic rewards are not tiered. Forgotten Research Lab and Treasure Expedition stay disabled (they need the treasure map item and a lab dungeon).
- Tests: `tests/unit/dungeons.test.ts`.
