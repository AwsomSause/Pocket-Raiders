# Story Overhaul S1b: story-loss rule, Variant Resolver, Module Validator

- **Story-loss rule** (`core/story2/loss.ts`, one small branch in `core/run.ts`): in a Story Run (`run.story.v2.mode === 'story_run'`) a lost **rival** fight (`battle.rivalId`, `rival` or `firstRival`) no longer ends the run. It reuses the M12 narrative-defeat tail: party healed, node counts as done, no prize/EXP/badge/win counters, and the loss is recorded (flag `sv2:loss:<rivalId>`, `v2.facts.story_losses`, a story moment that becomes a memory and a chronicle line). Classic Run and non-rival fights in a Story Run end as before. Story event fights join `storyLossApplies` when the event slices add them.
- **Variant Resolver** (`core/story2/resolver.ts`): pure scorer, specificity table from the design doc (backstory 10, input 15, relationship 12, flag 14, trait 6, starter 8, line 9, act 3), highest total wins, ties by authoring order, neutral line when nothing passes. Event variants and dialogue lines carry `when` conditions.
- **Module Validator** (`core/story2/moduleValidator.ts`): ids exist, 8+ events, 3+ echo events, encounter pool, Remembrance unlock, parity checklist, and the ending grid (every ending has a row, last row is the catch-all). `BackstorySchema` gained the manifest fields (all default empty, so empty data still passes the gates).
- Tests: `tests/unit/storyLoss.test.ts`, `tests/unit/storyResolver.test.ts`.
- **Not in S1** (needs writing, split per backstory): the vertical-slice content itself (Characters, Cast, Lore stubs, Events, Arcs) and renumbering/rewriting the design doc tables per S.2/S.3.
