# Overhaul slice 3: shared generator and pick history (run v39)

- Overhaul slice 3 (THE OVERHAUL.md rule 1, controlled randomness): `src/core/variety.ts` is the one "eligibility, then diversity" step every random pick can use. The caller's pool and weights decide what is eligible; anything picked within the last `balance.variety.window[pool]` picks of the same pool gets weight × `balance.variety.penalty` (0.35), never removed, so a pool can't run dry. Picks are remembered on the run in `run.history[pool]` (run save v39; older runs load with an empty history). API: `varietyWeight(content, run, pool)` (a weight multiplier, for pools that already build their own weights), `pickVaried(content, run, pool, candidates, rng)`, `rememberPick(content, run, pool, key)`. It never draws from an RNG itself, so it adds no stream.
- Wired today: wild Pokémon (window 5, keyed by evolution family; the wild pair counts too). Eggs, trades and trainer teams join in the variety slices 13–16 by adding a window for their pool in `balance.json`.
- Old-seed check (`tests/unit/story.test.ts`) switches it off (`variety: { penalty: 1, window: {} }`), like every later system. Tests: `tests/unit/variety.test.ts` (window and penalty, repeats drop by over 40% in a 300-pick run, every-candidate-recent boundary, empty pool error, a real run's history, v38 → v39 migration and save/reload).
- Limited: repeats are measured in a unit simulation; the 100-run check of how it feels comes in slice 29.
