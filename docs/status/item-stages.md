- Item stages (item rework part 2, Kice 2026-11-07: "most items should have three different stages in different rarities"): `core/itemStages.ts` builds a Stage II and Stage III copy of every catalog item that has numbers to grow, at content load (`withStages` in `data/index.ts`), so one data row makes three items: **846 new items** (catalog 1,014 -> 1,860). Stage II is one rarity up and 1.5x; Stage III two up (capped at epic) and 2x (`balance.itemStages.factors`). Grows percents, multipliers, money, heals, fractions, friendship, turns and counts; X items gain a whole stage each (+2, +3); attribute changes grow but **Luck never does**; descriptions are restated with the new numbers ("1/16" becomes a percent). Ids `<id>-ii` / `<id>-iii`, names "… II" / "… III", same icon and family, so the draft's family odds are unchanged. No stages for epic items, charms, or kinds/families where a stronger copy makes no sense (`skipKinds`/`skipFamilies`: TMs, fossils, natures, evolution/species items, memories, plates, key items, Tera/ability items, form-change items, perks, Bag items). No save bump (new ids only). Tests: `tests/unit/itemStages.test.ts`. Limit: stage copies share the base item's icon.
